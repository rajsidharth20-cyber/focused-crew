# Architecture rules
- Keep audio peer-to-peer and authorize short-lived call signals against accepted friendships and blocks in the database; a single account-scoped call provider owns microphone tracks and signaling cleanup across navigation.
- Resolve social notification recipients and text from saved actions on the server; public-post alerts target followed public accounts, never an unsolicited global audience.
- Snapshot delayed picker files into memory before previewing or compressing and upload that copy, because phone picker permissions may expire before Share or after asynchronous compression.
- Share account-scoped in-memory query snapshots for Social lists and apply live deltas to that cache, because tab remounts and presence readers must not duplicate reads or persist private conversations on disk.
- Hydrate auth and account/day-scoped planner snapshots synchronously as untrusted paint hints, then revalidate in the background; server authorization remains authoritative.
- Yield non-critical push setup and shared live subscriptions until after paint with cancellable scheduling, because startup must prioritize the dashboard without leaking connections.
- Persist objective mutations optimistically with operation-scoped rollback and exclude in-flight edits from startup revalidation, because slow requests must not overwrite newer local work.
- Dispatch social pushes with the shared atomic notification claims and per-device tracking, because failed or unregistered delivery must not be recorded as sent.
- Evaluate signed-in scheduled reminders only through the secret-authenticated backend scheduler, with atomic claims and per-device success tracking, because closed tabs cannot schedule and retries must not resend to successful devices.
- Preserve the reminder cursor on time-limited partial pages, because later users must not be starved by repeated restarts of a short final batch.
- Use data-only FCM payloads with one background service-worker display and shared foreground deduplication, because mixing automatic and manual display produces duplicate notifications.
- Enforce reporting thresholds and messaging restrictions transactionally at the database boundary, because client-only safeguards can be bypassed and concurrent reports must count reliably.
- Share one user-events Realtime channel per signed-in browser session, because mounting multiple social hooks must not multiply subscriptions.
- Keep study presence ephemeral on group and friend-scoped channels, because a study timer should not write heartbeat rows to the database.
- Share study Presence channels between publishers and readers with pre-registered handlers and reference-counted cleanup, because opening a timer must not add handlers to an already-subscribed channel or remove another consumer's connection.
- Load historical planner objectives only on demand from history or exports, because boot should transfer today's plan rather than 90 days of history.
- Import PDF rendering libraries inside export actions, because ordinary navigation should not load report dependencies.
- Send group messages only through the authenticated FocusBot handler, because direct client inserts would bypass server-side text and image moderation.
- Delete recurring series and append weekly notes through owner-scoped database functions, because deletion must be atomic and simultaneous notes must not overwrite one another; guest mutations use equivalent local helpers.
- Scope wall-clock ticks to timer display components, because the Home data owner must not rerender every second.
- Fetch recent study sessions at boot and compact older day totals for streaks; load detailed history on demand and persist only a bounded recent cache, because all-time session rows must not block startup or localStorage.
